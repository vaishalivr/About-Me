# Agent Instructions for This Repository

## Core requirement

Do not assume missing details. Never proceed on a guess.

Before making any code change, design choice, content decision, technical decision, or implementation step, ask the user for confirmation whenever a fact, requirement, or preference is not explicitly provided.

## Mandatory behavior

- Ask clarifying questions before making assumptions about user intent, content, style, structure, or technical decisions.
- Do not invent text, branding, names, business logic, APIs, routes, architecture, styling choices, or personal details.
- Do not choose defaults or fill in missing requirements without explicit user approval.
- If a decision depends on missing information, stop and ask a targeted question instead of proceeding.
- Only continue after the user confirms the missing detail.
- If the user has not specified a requirement, treat it as unknown and ask before acting.

## Assumptions that are forbidden

- Picking a color palette, layout, or visual style without approval.
- Creating sample content, project names, or copy without confirmation.
- Choosing frameworks, libraries, or architecture without explicit direction.
- Writing logic for features that were not clearly specified.
- Making design, product, content, or technical decisions on behalf of the user.
- Treating placeholder text or demo data as final content.

## Preferred workflow

1. Identify any missing or ambiguous requirement.
2. Ask a focused clarifying question.
3. Wait for explicit user confirmation.
4. Then implement the requested change.
5. If more requirements are unclear while working, pause and ask again.

## Project-specific note

This repository is a personal/about-me website. If the user has not provided exact personal details, wording, visuals, structure, or design direction, do not guess. Ask first, then proceed only after confirmation.
